Implementation

Tokens are the contract, utilities are the surface

The reference app aliases the DS variables into Tailwind v4’s @theme namespaces. No value is ever redefined — the CSS custom properties in tokens/ stay canonical, and Tailwind only borrows them. Component APIs (variant, size, block) port 1:1, so <Button variant="spark" size="lg"> means the same thing in both.

Two namespace rules

Text color roles get renamed. Tailwind v4 reserves --text-* for font-size pairs, but the DS also uses it for color roles (--text-primary, --text-price). Colors are remapped to ink, price, link, savings so the type scale keeps the --text-* names.

shadcn aliases point at Walmart tokens. background, primary, destructive, ring, card all resolve to DS values, so unmodified shadcn component code lands on-brand. One caveat: shadcn’s accent means “subtle hover surface” (Blue 50), not the DS’s Everyday Blue highlight — that one is accent-blue.

Keeping copies honest

Bundlers won’t resolve @import paths outside their project root, so the app vendors tokens/*.css into its own tree and re-syncs on demand. typography.css is the exception: its @font-face url()s are rewritten to the app’s public font path, so token-value edits there are applied by hand. Everything else copies verbatim.
